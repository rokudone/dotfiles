# crit を PR レビューで使うときのルール

crit の標準フロー（コメントに対応してコードを直し `crit comment --reply-to` で返信する）が成立するのは、レビュー対象が Claude 自身の作業物（自分の差分・plan）のときだけ。他人の PR に対して crit を使うときは構図が逆になる。

## 構図

- crit のコメントは、ユーザーが PR 作者に向けて書く指摘の草稿・相談材料。Claude への指示ではない
- 議論の場はこの会話。成果物は GitHub への PR レビューコメント
- PR 作者は crit セッションを見ない。crit に何を書いても誰にも届かない

## 禁止事項

1. crit にコメント・返信を書き込む際は、レビュワーの指摘に対してのコメントとして書き込む。レビュイーの視点ではない。
2. PR のコードを修正しない。他人の PR である

## 正しい流れ

1. Finish Review 後、crit のコメント一覧を議論の入力として読む
2. コメントを1件ずつ会話で議論する。ユーザーが投稿する・しないを決める
3. 確定した指摘は文面を一字一句提示し、承認を得てから GitHub へ PR レビューコメントとして投稿する
4. 投稿先・方法は manual-review 等の進行中フローがあればそれに従う
