# 担当範囲で区切って並列に任せる

## 1. 切り分け

1. 親が先に対象を機械的に列挙する（grep で該当箇所を集計、一覧の行を数える）
2. 班は件数ではなく境界（ディレクトリ、行番号の範囲、地方）で切り、範囲が重ならないようにする
3. 班をまたぐもの（複製ファイル、完全一致テスト、共通の定数）は親が最後に同期する担当として brief に書く

## 2. brief に必ず書くもの

1. 判定基準と除外条件を文で固定する
2. 返却の形を次の 4 部で指定する
   1. やったこと（件数）
   2. 迷って残したもの（理由つき）
   3. 担当外で見つけた参照・壊れたもの
   4. 推測で埋めた値（無ければ「無し」）。推測で埋めることそのものを禁じてもよい
3. 裏取りでは、各行に「判定・根拠 path:line・説明」を返させる
4. 編集の手段を指定するなら、auto mode の指示（Bash 優先）と衝突しないかを確かめてから書く

## 3. 返却の受け方

1. 全班が戻るまで表を確定しない。返却が「result truncated」で切れたら SendMessage で続きを取る
2. 見出しと本文の結論が食い違う行、推測の欄に載った行、「無い」という否定の結論は、親が該当箇所を開いて確かめてから表に入れる
3. 全班が戻ったら、全テストと整合性チェック（リポジトリにあるもの）を親が流す
4. 最終報告では、残したもの（基準に当たらなかったもの）を別枠で挙げ、範囲外の作業を混ぜない

## 4. fork と並べるとき

1. fork は親の子 agent の完了通知を受け取れないと見られている（観測 1 件。ハーネスの仕様では未確認）。待ち合わせは親が担い、fork には完成した入力だけを渡す
