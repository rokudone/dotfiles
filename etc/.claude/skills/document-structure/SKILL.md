文書は主張の木である。木の形を先に決め、文はその節点にだけ置く。

## 木の形

1. 根は、読者が読み終えたときに下す決定。一行で書けないなら書かない。
2. 節は、根に至るまでに読者が持つ問い一つに答える主張。見出しはその答えか、答えの対象。
3. 節の子は、その主張を支える物。全部同じ種類でなければならない。種類が変わるなら別の節を立て、導入の一文で切り替える。
4. 兄弟は依存の順に並べる。前の答えが次の前提になる。後ろを先送りで参照する必要が出たら、順序が違う。
5. 最初に分ける軸を決めてから細部を書く。軸の無い平らな列挙は木ではない。

## 文

1. 一つの文は一つの節点に属し、その節点の中身だけを言う。親の分類や隣の節点との関係を押し込まない。
2. 主張には帰結を付ける。何が起きるかまで書かないと、読者に問題を推測させる。
3. 節点でない文は入れない。現状の説明、理由の理由、文書自身の進行、言われていない反論への先回り、決定に効かない理由付け。
4. 比較は軸ごとに節点を立て、比較対象を同じ順序と同じ文型で並べる。
5. 用語は木の順に初出で定義する。
6. 一文の中で列挙しない。括弧や読点で項目を並べた文は、読者が数えながら読むことになる。列挙が要るなら、その文を親にして一段下げた箇条書きにする。列挙が要らないなら総称だけを書く。

## 箇条書き

1. 字下げは「子が親の中身である」の意味でだけ使う。原因と帰結、前と後の関係は親子ではない。
2. 同じ段には並列の物だけを置く。「代わりに」「そのため」「その結果」で始まる行は前の行に従属していて、兄弟にならない。
3. 従属する行を一段ずつ下げても構造にはならない。一人っ子が続く階段は、並列の面をまだ見つけていない印。
4. 書く前に、その節が答える問いを一つに定め、答えを並列の面に分ける。面の名前を行頭に置く。
5. 複数の面に共通する理由や条件は、親の行に入れる。
6. 対になる節（現状と方針、変更前と変更後）は同じ面を同じ順序で並べ、一対一に対応させる。
7. 文章を行ごとに切って箇条書きへ移さない。名詞止めの断片を並べることも、句点付きの文を並べることも、構造を取ったことにならない。
8. 元の資料に無い推測を、つなぎのために足さない。

悪い例。三行は並列に見えるが、二行目は一行目の帰結、三行目は二行目の代替で、どれも兄弟ではない。

```markdown
- 年末年始は休業日
- 定期サービスの予約を生成しない
- 代わりに、スポット1件を定期料金で利用できるようにしている
```

悪い例。従属を字下げに移しただけで、子は親の中身ではない。

```markdown
- 年末年始は休業日
    - 定期サービスの予約を生成しない
        - 代わりに、スポット1件を定期料金で利用できるようにしている
```

良い例。問いは「年末年始の定期サービスをどう扱うか」。面は予約と利用の二つ。休業日は共通の理由なので親に入る。方針の節は同じ二面で現状と対応する。

```markdown
### 背景

- 年末年始は休業日のため、定期サービスを次のように扱っている
    - 予約：生成しない
    - 利用：スポット1件を定期料金で利用できるようにしている

### 基本方針

- 年末年始の定期サービスの扱いを、次のように変える
    - 予約：他の日と同じように生成する
    - 利用：生成した予約を、別の日へ振り替えて利用する
```

## 書き方

1. 骨だけ先に出す。主張と項目名だけを書き、支えは骨が通ってから足す。
2. 読者の決定に使われない物は別の文書にする。実測、経緯、個人の環境、目的の異なる手順。

## 点検

1. 見出しだけで論証が追えるか。
2. 各節の最初の段落が問いに答えているか。
3. 各節の子が一種類か。軸があるか。
4. 節点でない文が無いか。帰結の無い主張が無いか。
5. 先送り参照、定義前の用語が無いか。
6. 箇条書きの兄弟が並列か。「代わりに」「そのため」で始まる兄弟、一人っ子の階段が無いか。
