# qa-doc-server

Claude が書いた文書をローカルで読ませ、箇所を指した質問を受け取り、同じ画面に回答を返す仕組み。構成は三つで、すべてプロジェクトディレクトリ内に閉じる。外部通信はない。

1. `server.py`。`127.0.0.1:8765` で HTML を配信し、`/api/questions` で質問を受けて `questions.jsonl` に一行追記する。
2. `qa.js` と `qa.css`。各ページが読み込む。本文の外側に左のページ一覧と右の質問欄を組み立て、本文選択から質問を送り、5 秒ごとに回答を取り直して表示する。
3. Claude 側。`questions.jsonl` を監視し、`answer` が `null` の行を Edit で埋める。

ユーザーは本文を選択して「質問」を押し、文を書いて送る。Claude は通知を受けてファイルを編集する。回答は数秒でページに出る。

## 手順

### 1. ファイルを配置する

対象ディレクトリ（文書を置く場所）に、このスキルの `assets/`（Skill ツールが示す base directory 直下）から三つをコピーする。Read してから Write で書き出す。

1. `assets/server.py` → `<dir>/server.py`
2. `assets/qa.js` → `<dir>/qa.js`
3. `assets/qa.css` → `<dir>/qa.css`

既に同名ファイルがあるときは、ユーザーが改変している可能性があるので上書きせず差分を確認する。

### 2. 文書を HTML で書く

Markdown を書いて変換する形は取らない。変換層があると、ユーザーが「HTML から直接」と求めたときに手戻りになり、見出し id の付け方も変換器任せになる。`assets/page-template.html` の形で直接書く。

ページ側の要件は三つ。これを満たさないと質問の節特定とナビが動かない。

1. 本文を `<main id="main">` の中に置く。`qa.js` はこの要素の外側にレイアウトを組み、選択範囲がこの中にあるときだけ「質問」ボタンを出す。
2. 見出し `h1`〜`h4` に id を付ける。番号付き見出しなら `s1`、`s1-2` のように番号由来にする。質問にはこの id と見出し文が付くので、Claude が回答時に箇所を特定でき、回答欄のリンクから本文へ戻れる。
3. `<head>` で `qa.css` を、`</body>` 直前で `qa.js` を読み込む。先頭にスラッシュを付けない相対パスにする。絶対パスにすると、ユーザーがファイルを直接開いたときにディスクのルートを探してスタイルが当たらない。

ファイル名は `00-plan.html`、`01-intro.html`、`day03-scope.html` のように「連番または day 番号、ハイフン、名前」にする。サーバーはこのパターンのファイルだけをページとして一覧に載せ、`/01` や `/day03` で配信する。先頭のファイルが `/` になる。`<title>` の「:」または「：」より前がナビの表示名になる。

本文の書式は `qa.css` が `p` `ol` `ul` `table` `code` `pre` を整えるので、素の HTML で足りる。

### 3. 起動して確認する

```
cd <dir> && python3 server.py
```

Bash の `run_in_background` で起動する。起動行は `http://localhost:8765` を flush 付きで出す。ポートは環境変数 `PORT` で変えられる（`PORT=8766 python3 server.py`）。同じマシンで別の文書サーバーが既に 8765 を使っているときはこれで分ける。以下の URL と監視コマンドのポートも合わせて読み替える。

確認は `curl` が許可されないことがあるので、Python の `urllib` で各パスを取りに行く。

```
python3 -c "import urllib.request as u; [print(p, u.urlopen('http://localhost:8765'+p).status) for p in ['/','/qa.js','/qa.css','/api/pages']]"
```

動作確認で `/api/questions` にテスト質問を POST したときは、確認後にその行を `questions.jsonl` から消す。残すとユーザーの画面に「回答待ち」として出続ける。

ユーザーには URL と「本文を選択して質問を押す」操作、起動コマンドを伝える。

### 4. 質問を監視して回答する

Monitor ツールで `questions.jsonl` を監視する。Claude 自身が回答を書き込むと `tail -F` がその行も拾うので、未回答の行だけに絞る。

```
tail -n 0 -F <dir>/questions.jsonl 2>/dev/null | grep --line-buffered '"answer": null'
```

`timeout_ms` は最大の 1800000 にし、期限切れの通知が来たら付け直す。

質問が届いたら、その行を Edit で書き換えて `"answer": null` を回答文字列にする。回答は `white-space: pre-wrap` で表示されるので、改行はそのまま使える。回答の文体はユーザー向けの通常の文体でよい。Markdown は解釈されないので記法は使わない。

質問の行の形は次のとおり。

```
{"page": "day01", "section": "s4-2", "section_title": "4.2 組織のプロセス資産", "quote": "選択された本文", "question": "質問文", "id": 3, "asked_at": "2026-10-28 23:14:45", "answer": null}
```

`quote` と `section_title` で箇所が分かるので、回答はその箇所の文脈に即して書く。本文の該当節を読み直してから答えると、本文との矛盾を避けられる。

## 設計の理由

質問の保存先を localStorage ではなくサーバー側のファイルにしているのは、Claude がセッションから読んで書き込める場所が必要だから。ブラウザに閉じた保存では Claude から見えない。

Artifact を使わないのは、ユーザーが外部公開を避けたい場面が多いから。この構成は `127.0.0.1` にしか bind せず、ファイルもプロジェクト内に留まる。

依存を Python 標準ライブラリに限定しているのは、どの環境でも `python3 server.py` だけで動かすため。パッケージの導入を挟むと、その段階で止まることが多い。

## 既知の制約

1. Monitor は最長 30 分で切れる。長い読書セッションでは期限切れ通知のたびに付け直す。
2. ページ一覧はサーバーがディレクトリを都度読むので、HTML を追加すれば再起動なしで一覧に出る。`server.py` 自体を変えたときだけ再起動する。
3. 質問の節特定は「選択位置から前方に遡った直近の見出し」で行う。見出しのない本文では空になる。
4. 同時に複数のユーザーが使うことは想定していない。
