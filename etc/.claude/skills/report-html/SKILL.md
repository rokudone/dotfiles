# Notion風ダイジェストHTML生成

長文資料を、認知負荷の低い1枚のダイジェストHTMLに変換する。実績: masa_wunder の統合ドキュメント29本（merged/digest/ 配下）。

## テンプレート

`/Users/filriya/.claude/skills/report-html/template.html` を Read し、`<style>` 全体と構成要素の使い方をそのまま流用する。CSSは改変しない（配色・フォント・余白が仕上がりの同一性を決める）。

構成要素:

1. `.kicker` — 冒頭の小ラベル（例: READING DIGEST 05）
2. `h1` + `.lede` — タイトルと1文の説明
3. `.meta-table` — 元資料の一覧表（番号・タイトル・日付・幹/補）。タイトルは原文URLへのリンク
4. `.thesis` — 中心主張の帯（💡）。主張が明確な文書のみ。冒頭に置き、強い文書は末尾に再掲
5. `h2`/`h3` + `<span class="src">` — 見出しと出典番号。番号は原文URLへの `<a>` にする
6. `.note` — 余談・注意・用語（📌）。本文の流れから逃がす
7. `.takeaway` — 末尾の「持ち帰り」（3〜5点のol）
8. `.docfoot` — 生成元ファイルの記載

## 本文の書き方

1. 原文の文章は残さず要約し直す。分量は元の1/5〜1/10（大きい元は1/10目安）。読了数分
2. 地の文より箇条書きを優先する。並列事項はul、手順・順位・段階はol。段落は導入と橋渡しのみ
3. 要点は `<li><strong>ラベル</strong> — 補足</li>` の形にする
4. 数値・ツール名・コマンド・固有名詞は要約後も必ず残す。比較・一覧は表にする
5. 本文が不完全な元資料（有料の試し読み等）は .note でその旨を明記する
6. 文体は標準語の淡々とした解説調

## SVG図解の作法

1. 内容に実際にある構造だけを図にする。層→積み層図、流れ・役割分担→フロー図、2軸分類→2x2マトリクス、段階→階段図、対立→左右対比。内容にない構造の捏造は禁止
2. 1本あたり2〜5枚。template.html に3種の実例（積み層・フロー・マトリクス）がある
3. `viewBox="0 0 680 高さ"`、塗りは `var(--f1〜--f4)`（薄→濃）、枠は `var(--s1〜--s3)`、矢印・強調は `var(--accent)`、文字は `var(--ink)` / `var(--sub)`。生の色コードを使わない
4. 図は viewBox 内で左右バランスよく配置し、片側に空白を残さない（過去の失敗: 縦軸ラベル用に左120pxを空けたまま削除して右寄りになった）
5. figcaption は「図N 要点を1文で」

## 落とし穴

1. `.note` / `.thesis` に display:flex を使わない。テキストノードと `<b>` が別の flex item に分解されて崩れる（テンプレートは block + ::before で修正済み）
2. `<style>` を自作しない。必ずテンプレートから複製する
3. 出典リンクは元資料側の索引（例: masa_wunder なら index.md を「| 251 |」でgrep）からURLを取得する。URLを推測で書かない

## 量産する場合

複数本を作るときは、subagent を1本1体で並列に起動してよい（このスキルが worker spawn を明示的に指示する）。各 subagent には、テンプレートのパス・入力md・出力パス・上記ルール一式をプロンプトで渡し、最終テキストには出力パスと図解一覧のみ返させる。完了後、メインで全ファイルの存在とサイズを検収する。

複数本ある場合は同スタイルの目次ページ（index.html）も作る。実例: /Users/filriya/Documents/note/masa_wunder/merged/digest/index.html
